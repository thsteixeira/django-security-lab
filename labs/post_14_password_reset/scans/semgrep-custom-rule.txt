          ❰❰ Blocking ❱❱
          This view takes a reset token from the URL and calls set_password(), but never calls check_token().
          A token that is only looked up - not verified - carries no expiry and no binding to the account's  
          current state, so a reset link that leaked (proxy log, browser history, Referer, mailbox backup)   
          stays a working credential indefinitely, and a link already spent can be replayed. Verify with     
          django.contrib.auth.tokens.default_token_generator.check_token(user, token) before the write: its  
          hash input includes the user's password hash, last_login and a timestamp, so the token expires     
          against PASSWORD_RESET_TIMEOUT and self-invalidates the moment the password changes. Better still, 
          use django.contrib.auth.views.PasswordResetConfirmView, which does this for you.
